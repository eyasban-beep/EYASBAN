# 길드전 자원 조사 (Cloudflare Pages)

클랜원이 매주 월요일 자원 수량을 올리면 **계수를 곱해 점수를 계산**하고, **안 낸 사람을 표시**하는 웹페이지.
게임 프로젝트(`Game/`)와는 별개인 클랜용 도구다. 게임 이름·로고·아이콘은 페이지에 넣지 않았다.

## 기능
| 탭 | 내용 |
|---|---|
| 제출하기 | ① **한 칸씩 입력**: 닉네임 선택 → 항목마다 숫자 입력<br>② **한 줄로 붙여넣기**: `daye, 스킬뽑기 346k, 펫알 118k, 펫합성 1840개, …` → 미리보기 확인 후 제출<br>숫자는 `346k`, `2.7k`, `1.2m`, `1,840개`, `3만` 모두 인식. 같은 주에 다시 내면 덮어씀 |
| 현황·점수 | **미제출자** 표시 + **카톡 재촉 메시지 복사** (문구는 관리자가 편집)<br>**클랜전 일자별 예상 점수**: Day 1~5 날짜별·자원별 포인트 합계<br>**취합표**: 클랜원 전원 × 자원 표 (미제출은 빨간 줄), 제목 눌러 정렬, 엑셀 붙여넣기 복사, CSV 저장(이 주 / 전체 주) |
| 관리자 | 비밀번호 로그인 → **항목·계수·쓰는 날(D1~D5)** 편집, **카톡 재촉 문구**, **클랜원 명단**, 잘못된 제출 삭제 |

- 주차 = **한국 시간 월요일 00:00 ~ 일요일 23:59**. 월요일 0시가 되면 자동으로 새 주가 시작되고 전원이 다시 '미제출'이 된다.
- 클랜전: 조사 주 월요일 다음 날(화)이 Day 1, 토요일이 Day 5, 일요일 Day 6은 공격일(자원 점수 없음).
- 기본 계수·쓰는 날 (forgemaster.pro 클랜전 표, 게임 2.11.1 기준 — 게임 업데이트 시 관리자 탭에서 고칠 것)
  | 자원 | 계수(개당) | 쓰는 날 |
  |---|---|---|
  | 스킬뽑기 | 125 | D1, D3 |
  | 펫알 | — | 집계만 (클랜 합계만) |
  | 펫합성 | 1,250 | D3, D5 |
  | 탈것뽑기 | 600 | D2, D4 |
  | 탈것합성 | 600 | D2, D4 |
  | 초록물약 | — | 집계만 (길드 테크트리용, 클랜 합계만) |
- **쓰는 날을 하나도 체크하지 않은 항목 = 집계만**: 점수에서 빠지고 클랜 합계만 표시.
- 일자별 표: 두 날에 쓸 수 있는 자원은 반씩 나눠 계산. 한 날에 몰아 쓸 계획이면 그 날만 체크.
- 점수 = Σ(수량 × 계수). 계수는 저장된 숫자에 매번 곱하므로, 계수를 바꾸면 지난 주 점수도 새 계수로 다시 계산된다.

## 파일 구조
```
tools/clan-survey/
├─ public/            ← 화면 (index.html, style.css, app.js, parse.js)
├─ src/api.js         ← 서버 (/api/... 요청 처리, D1 저장)
├─ src/worker.js      ← Workers 방식 입구
├─ functions/api/[[route]].js ← Pages 방식 입구 (같은 src/api.js 사용)
├─ wrangler.jsonc     ← Workers 배포 설정 (D1 이름 clan-survey 자동 연결)
└─ schema.sql         ← DB 표 구조 (참고용, 서버가 처음 실행될 때 자동으로 만듦)
```

## 배포 방법 (Cloudflare Workers + GitHub, 처음 1번만)

1. **D1 데이터베이스**: 스토리지 및 데이터베이스 → D1 → `clan-survey` 생성 (✅ 완료)
2. **컴퓨트 → Workers 및 Pages → 애플리케이션 생성 → Git 리포지토리 가져오기** → `eyasban-beep/EYASBAN`
3. 애플리케이션 설정 화면
   | 칸 | 값 |
   |---|---|
   | 프로젝트 이름 | `clan-survey` |
   | 빌드 명령 | 비워 둠 |
   | 배포 명령 | `npx wrangler deploy` (기본값 그대로) |
   | 고급 설정 → 경로(루트 디렉터리) | `tools/clan-survey` |
   → **배포**
4. 브랜치: GitHub 저장소의 기본 브랜치에 이 코드가 없으면 첫 배포가 실패한다.
   프로젝트 → 설정 → 빌드 → 분기 제어 → 프로덕션 분기를 `claude/determined-clarke-ekn93g` 로 바꾸고 다시 배포.
5. `https://clan-survey.<계정이름>.workers.dev` 접속 → **관리자 탭에서 비밀번호를 처음 정함** (먼저 들어온 사람이 정하게 되니 배포 직후 바로 할 것)
6. 클랜원 명단 입력·저장 → 주소를 클랜 공지에 올리기

- DB 연결은 `wrangler.jsonc` 에 적힌 이름(`clan-survey`)으로 배포 때 자동으로 된다. 대시보드에서 바인딩을 따로 추가할 필요 없음.
- 관리자 비밀번호는 관리자 탭에서 바꿀 수 있다. (환경 변수 `ADMIN_PASSWORD` 를 넣으면 그 값이 우선)
- 선택: 환경 변수 `CLAN_CODE` 를 넣으면 제출 때 클랜 코드를 묻는다.

## 매주 쓰는 법
- **클랜원**: 월요일에 접속 → 제출하기 → 둘 중 편한 방식으로 입력 → 제출
- **관리자**: 현황·점수 탭 → `💬 카톡 메시지 복사` → 단톡방에 붙여넣기 / `표 복사` 또는 `CSV 저장` → 엑셀·구글시트

## 코드를 고쳤을 때
GitHub의 Production branch에 push하면 Cloudflare가 자동으로 다시 배포한다 (1분 정도).
